# ⚡ Outage Intelligence: Grouping Outage Reports into Possible Incidents

**Smart Caribbean Utilities · End-of-Year AI Project 2026 · Associate of Science in AI, Amber National AI Lab**
**Group 19** · Project C: AI Outage Intelligence

> **Research Prototype: Simulated Utility Data.**
> All service zones, outage reports and locations in this project are **fictional**. No real customers, names, addresses or meter data are used. Nothing here represents a real utility company.

---

## 1. What this project does

During a storm, an operator may receive hundreds of separate outage reports. This prototype:

1. Creates simulated outage reports (time, location, zone, description, customers affected).
2. Plots them on a map.
3. Groups nearby reports into **possible incidents** using DBSCAN.
4. Shows incident counts and affected zones.
5. Produces a **priority list** using clear, written rules (not AI guesses).

**Intended user:** a control-room operator deciding which areas to send crews to first.

**What the AI does *not* do:** it does not know the *cause* of an outage. It only groups reports by place (and, later, time). Output is a *possible incident*, never a confirmed cause.

## 2. Quick start

### Requirements
- Python 3.10 or newer
- Git

### Install

```bash
# 1. Get the code
git clone https://github.com/<your-username-or-org>/outage-intelligence.git
cd outage-intelligence

# 2. Create and activate a virtual environment
python -m venv .venv

# Windows:
.venv\Scripts\activate
# Mac / Linux:
source .venv/bin/activate

# 3. Install libraries
pip install -r requirements.txt
```

### Run the app

```bash
streamlit run app.py
```

The app opens in your browser at `http://localhost:8501`.

The app works **offline**: all data is generated locally, with no internet or API keys needed.

## 4. Data

| Item | Detail |
|---|---|
| Source | Synthetic: generated by `modules/data_gen.py` |

| Columns | `time`, `lat`, `lon`, `zone`, `description`, `customers_affected`, `true_incident` |

| Reproducibility | A fixed random seed (`SEED` in `config.py`) gives the same data every run |
| Licence / privacy | Fully synthetic; no personal data |

## 5. How the AI works

- **Method:** DBSCAN, a clustering method that groups points that are close together and leaves isolated points alone. Two settings matter: the distance (`eps`, about 1 km) and the minimum reports in a group (`min_samples`).
- **Baseline (no AI):** group reports by service zone only.
- **Priority list:** transparent rules, e.g. customers affected and whether a hospital is in the zone. The rules are written in `modules/` and explained in the app.

## 7. Limits

- Data is **simulated**. Results show the software works, not that it would work on a real grid.
- Clustering depends on the `eps` and `min_samples` settings; poor settings can merge separate incidents or miss small ones.
- The model groups by location only; it cannot identify the physical cause of an outage.
- A real utility would also need real outage-management data, network topology (which feeder serves which street), and operator validation.
